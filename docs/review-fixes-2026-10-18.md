补充优化：Webhook 改用事务性持久化投递队列，重启后恢复、退避重试、同规则/主机有序投递，并带稳定投递 ID；Windows 在 UI 入队前合并传输进度；三端探针以 `shared/probes` 为源生成，CI 检查一致性；Web Docker 完成回调检查页面作用域；macOS 会话由 SessionManager 持有，关闭和目标编辑清理生命周期。

Web 性能基准和复现脚本见 [性能记录](../web/frontend/benchmarks/performance.md)。相同本地测试中，1000 台主机的 5.5 秒空闲窗口主线程工作从 73 ms 降至 21 ms；约 2 MiB 文本输入 20 个字符从 343 ms 降至 221 ms，输入期间重复全文 UTF-8 编码从约 41.9 MB 降至零。这是单次配对开发测量，不能视为所有设备的保证；保留了可重复测量脚本。

新增回归覆盖真实失败路径，包括特殊文件名、主机密钥拒绝、连接淘汰、活动传输与取消、托盘隐藏状态、Docker 迟到结果、改密码请求乱序、跨页配置修改、201 个活动告警、多指标峰值、Unicode 增量文本统计、批任务取消以及 12 个同时访问者只查询一次。

PostgreSQL 集成测试仅在显式设置 `SERVER_MONITOR_TEST_DATABASE_URL` 时运行，创建独立测试 schema，验证备注隔离、205 个活动事件翻页、通知事务回滚、并发认领、失败重试与重启恢复。它不读取应用的 DATABASE_URL。Linux CI 提供专用 PostgreSQL 16，并执行 Go race 检测；macOS CI 使用严格并发及 warnings-as-errors 编译测试。

本地最终检查：Windows 532 通过、14 live 跳过；前端 build/lint 通过，93 项浏览器回归通过、1 项生产 readiness 跳过；Go 测试与 vet、共享探针同步、发布脚本离线测试通过。PostgreSQL 与 Swift 的运行验证由 CI 补齐。

行为边界：macOS 目录浏览要求 GNU find，不能无损解析时明确失败；SFTP 服务端不支持原子替换且目标已存在时，Windows 拒绝覆盖并保留原文件；临时文件写入前为 0600，已有目标保留原权限和 UID/GID，新文件默认为 0600；断网可能留下唯一临时文件。批任务取消不能保证远端已启动的进程结束。Webhook 为至少一次投递，接收方应按投递 ID 去重，恢复通知会等待前序触发通知送达。
